# ART PIPELINE: Blender → Roblox (APPROVED, D-011)

## Решение
Гибридный пайплайн. Не «всё в Blender» и не «всё боксами», а три уровня:

| Уровень | Что это | Где делается | Когда используется |
|---|---|---|---|
| **L0 Hero** | Цельные детализированные здания/корабли, 1–3 MeshPart на объект, 3 LOD | Blender → FBX → Roblox MeshPart | Большинство зданий в городах, корабли, уникальные объекты |
| **L1 Kit** | Модульные куски (стена с окном, скат, угол, балка), собираются в игре | Blender → FBX → Roblox, сборка кодом | Вариативная фоновая застройка, окраины |
| **L2 Blockout** | Процедурные боксы (текущие генераторы) | Luau | Плейсхолдеры, тесты, дальние чанки/импосторы |

Правило: **геймплей никогда не зависит от уровня арта**. `MeshBuilding`/`Builder` возвращают одно и то же — модель в Workspace, только разной степени детализации. Нет ассета → автоматический фолбэк на боксы.

## Почему так
- **Blender**: настоящие фаски/скругления, сваренные вершины, нормали, UV, PBR; можно сделать LOD через Decimate. Без этого «коробочность» не победить.
- **Roblox**: MeshPart дешевле по частям (1 объект вместо 260 Part) и быстрее для рендера, но каждый ассет грузится с модерацией и имеет лимиты.
- **Процедура**: даёт бесконечную вариативность и нулевую стоимость ассетов; на героях проигрывает по качеству.

## Технические правила (жёсткие)
1. **Единицы**: Blender scene unit = 1 м, FBX export `apply_scale_options='FBX_SCALE_ALL'`. В Roblox 1 м = 3 studs — масштаб применяет импортер/скрипт, не модель.
2. **Pivot**: основание по центру (`base_center`), низ модели на Y=0. Фасад смотрит в **−Z Blender** (после импорта Roblox → +Z вперед). Проверяется скриптом `hero_export.py --validate`.
3. **Ориентация**: импорт «Y up», forward −Z. Не менять без записи в DECISIONS.
4. **Бюджет треугольников**: hero-здание ≤ 12k tri (L0), L1 ≤ 35%, L2 ≤ 8% (или 1 бокс-импостор).
5. **Материалы**: не более 3 на объект (атлас `Primary`/`Secondary`/`Glass`), UV — Smart Project с отступом 4 px, текстура 1024–2048.
6. **Имена**: `TH_<ФРАКЦИЯ>_<ТИП>_<ВАРИАНТ>` (напр. `TH_ARK_House_02`), LOD — суффиксы `_L1`, `_L2`. Совпадает с `ASSET_REGISTRY.md`.
7. **Форма**: только «земная» стилистика — никаких неоновых/футуристичных форм; палитры строго `DESIGN_TOKENS.md`.
8. **Файлы**: `blender/export/<faction>/<name>.fbx` + `manifest.json`. В репозиторий FBX не коммитим — только скрипты и манифест.

## Как это выглядит по шагам
3. Импорт в Roblox Studio: **3D Importer** (FBX) → `ReplicatedStorage/TH_Art/<name>`; в свойствах — `Anchored = true`, `CanCollide` по типу.
4. Прописать asset id (или имя Model в ReplicatedStorage) в `TH_Shared/Config/MeshAssets.lua` (создаётся в Ф5 (арт-пайплайн)).
5. В игре `MeshBuilding.build(...)` берёт меш, ставит по `base_center`, при отсутствии — падает в `Builder` (боксы) с логом `[TH] mesh fallback`.

## Проверка качества (гейт A-1)
- [ ] Pivot и масштаб: здание 8×7 м в Roblox = 24×21 stud, низ на уровне земли.
- [ ] Нет «провалов»: у модели нет открытых торцов (backface culling) и щелей между стенами.
- [ ] Тени: при `CastShadow=true` нет артефактов самозатенения (нормали сварены).
- [ ] LOD-переключение без щелчков: L1 силуэт совпадает ±5%.
- [ ] Палитра: цвет материала = HEX из токена; при текстурах — surface appearance.
- [ ] Blender-скрипт запускается с нуля на чистой сцене (нет зависимости от порядка файлов).

## Ограничения, которые надо знать
- Blender на машине владельца; в этой сессии он не установлен — скрипты не прогонялись, только статически проверены.
- Импорт FBX в Roblox может требовать ручных шагов (Roblox 3D Importer), автоматизировать из Luau нельзя.
- Модерация ассетов занимает время; до публикации используется фолбэк L2.
