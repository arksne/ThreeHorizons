# WORLD NETWORK ARCHITECTURE (APPROVED v0.1)

## 1. Модель мира
Логически единый мир, физически — шарды (Roblox-места/инстансы) по 60–80 игроков. Шарды: 3 столицы + Эстерхольм-хаб + небо-коридоры. Переход — TeleportService между местами с переносом профиля (кэш MemoryStore 60 с).

## 2. Состояния
- Локальное (клиент): камера, предикт движения корабля, UI, туман карты.
- Серверное (инстанс): позиции кораблей/NPC рядом, бои, торговля, погода-эффект.
- Глобальное (кросс-шард): погода-фаза, мировые события, аукционы/контракты, офлайн-флот — через MemoryStore (TTL) + MessagingService (pub/sub) + DataStore (долгое хранение).

## 3. Синхронизация
- День/ночь и погода: один лидер-шард (Эстерхольм-1) публикует тик каждые 10 с (unix + фаза); остальные следуют. Дрейф ≤ 2 с.
- Мировые события: аренда в MemoryStore (`event:<id>`), подписка всех шардов; одно событие — один id, без копий на игрока.
- Корабли: репликация CFrame 10 Гц рядом (<500 st), 2 Гц далеко; владелец пишет намерения, сервер валидирует (скорость/топливо/перегруз).
- NPC: в радиусе игроков — полная симуляция; вне — агрегированные расписания (Schedules.lua).

## 4. Конфликты
Захват корабля/покупка: Compare-And-Set через MemoryStore UpdateAsync + DataStore UpdateAsync (идемпотентный ключ транзакции). Двойная трата невозможна: списание и начисление в одной транзакции Wallet.lua.

## 5. Лимиты Roblox (учтены)
MessagingService ~1000 msg/min на сервер — батчим тики; MemoryStore 100k ops/min — ключи с TTL; DataStore — Get budget + кэш профиля в памяти. Все вызовы в pcall с очередью повторов.
