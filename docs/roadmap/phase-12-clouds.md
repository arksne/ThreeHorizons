# Ф12 · Облака и облачное море v0.1

> **Цель:** живое облачное море и погода, которые видно и которые влияют на игру. Без мешей —
> только проверенная схема «нативные облака + альфа-клочья + атмосфера».
> **Зависит от:** Ф9 (мир)
> **Канон:** `CLOUD_SYSTEM.md`, `DESIGN_TOKENS.md` §свет,
> `SPECS_COMBINED.md` (камера/погода), решение D-012 (меш-облака запрещены)

## Правила фазы

- **Никаких меш-облаков.** Проверено: полигонами не получить просвечивание и мягкий край; это «вата»
  и лишний CPU. Только три слоя.
- Физика — чистый Luau (`CloudField`), без Roblox API: тестируется офлайн, детерминирована по seed.
- Пуфы — только вокруг игрока, лимит 6 активных, живут 6 с, плавно растворяются.
- Погода — данные, не хардкод: пресеты из `Config/Clouds.lua`.

## Шаги

### 12.1 · Схема трёх слоёв (зафиксировать)
- **Действие:** записать в DECISIONS: дальний план — нативные `Lighting.Clouds` + `Atmosphere`;
  средний — альфа-клочья на скрещённых плоскостях; внутри облака — локальные пуфы у игрока.
- **Готово, когда:** в `docs/DECISIONS.md` есть запись о трёх слоях; **проверка
  кодом:** `grep -ri "mesh\|EditableMesh\|UnionOperation" ROBLOX_IMPLEMENTATION/src`
  не находит ни одного меша-облака — только `Lighting.Clouds` / `Atmosphere` /
  альфа-плоскости.

### 12.2 · `TH_Shared/Sim/CloudField.lua`
- **Действие:** LCG-детерминизм (seed → одно небо), высотный ветер (`mul = 0.6 + alt*1.1`),
  порывы, заворот мира 12×12 км, плотность как сумма эллипсоидных спадов, видимость
  `1 − 0.85·density`, турбулентность (вектор для качки).
- **Готово, когда:** офлайн-тесты: детерминизм, заворот, плотность в центре/на краю/снаружи,
  10 минут симуляции без NaN — **15/15 PASS**.
- **Канон:** `CLOUD_SYSTEM.md` §2.3.

### 12.3 · Пресеты погоды
- **Действие:** `Config/Clouds.lua`: `clear/overcast/fog/storm` → `Cover`, `Density`, цвет,
  `Atmosphere Density`, `Haze` (значения из документа), плюс длительность и порядок перехода.
- **Готово, когда:** в `Config/Clouds.lua` ровно 4 пресета (`clear`/`overcast`/`fog`/`storm`),
  у каждого 6+ полей (Cover, Density, цвет, Atmosphere Density, Haze, длительность);
  **числа сервиса — ноль:** `grep -E "Cover|Density|Haze" ROBLOX_IMPLEMENTATION/src` находит
  только чтение из конфига, ни одной константы.

### 12.4 · Текстуры клочьев
- **Действие:** генератор `tools/make_cloud_puff_textures.py` (создаётся в этом шаге): фрактальный value-noise + кластер
  из 9 клочьев + радиальное затухание → мягкий рваный край; 4 PNG 512² RGBA. Загрузить в Roblox,
  id прописать в `Clouds.TEXTURE_IDS`.
- **Готово, когда:** 4 текстуры загружены, id в Config, клочья не «вырезанные кружки».
- **Канон:** `CLOUD_SYSTEM.md` §2.2; `TEXTURE_PIPELINE.md`.

### 12.5 · `CloudSystem.applyWeather(state)`
- **Действие:** серверный модуль ставит `Lighting.Clouds` и `Atmosphere` по пресету; API
  `densityAt/visibilityAt/turbulenceAt/applyWeather/puffCount`.
- **Готово, когда:** смена пресета в Play меняет небо; API отвечает числами (проверить в Output).

### 12.6 · Пуфы вокруг игрока
- **Действие:** модель из 9–12 плоскостей (Part + SurfaceGui/ImageLabel, лицо и тыл), эмиссия при
  `density > 0.25`, лимит `PUFF_MAX_ACTIVE = 6`, `PUFF_LIFETIME_S = 6`, fade; `CanCollide/Query/Touch = false`.
- **Готово, когда:** STUDIO — в Play при `density > 0.25` появляются клочья и растворяются
  за 6 с; **лимиты держатся:** одновременно ≤ 6 пуфов (`puffCount` в Output ≤ 6),
  `CanCollide/CanQuery/Touch = false` у всех частей пуфа, parts от пуфов ≤ 6 × 12.

### 12.7 · Облачное море (слой поверхности)
- **Действие:** 3 слоя плоскостей (Lower/Middle/Upper) с дрейфом и покачиванием; текстуры
  `TH_TEX_CloudSea_00..03`, `StudsPerTile` по слою; режим — вокруг острова (ground/sky-вариант).
- **Готово, когда:** море выглядит бесконечным, слои двигаются с разной скоростью, край скрыт туманом.
- **Канон:** `CLOUD_SYSTEM.md` §2 (три слоя: нативные Clouds + альфа-клочья + Atmosphere), решение S-06.

### 12.8 · Погодный цикл
- **Действие:** `WeatherService` — фазы по таймеру, смена раз в N минут, `applyWeather` на смене;
  клиент получает только состояние, физику поля считает одинаково по seed.
- **Готово, когда:** STUDIO, 2 клиента — оба видят одну фазу погоды (состояние приходит
  с сервера, не считается на клиенте); переход между фазами длится 10–20 с **без скачка**:
  значения `Cover`/`Density` на кадрах до/после отличаются ≤ 20 % за секунду.
  Офлайн: `tools/test.ps1` — тесты `CloudField` 15/15 PASS.

### 12.9 · Влияние на игру (v0.1)
- **Действие:** видимость (Fog/Atmosphere меняет дальность), навигация (флаг `navigable` для корабля),
  множитель износа/расхода топлива (числа из `Weather.json`).
- **Готово, когда:** числа влияния взяты из `GAME_DESIGN/Weather.json`, а не из кода
  (`grep` по src не находит литералов `visibilityMultiplier`/`wearMultiplier`);
  STUDIO — в шторм `FogEnd` уменьшается (видимость падает) относительно `clear`;
  флаг `navigable` в шторм = false (проверяется после Ф10).

### 12.10 · Замеры
- **Действие:** parts от облаков, FPS в ясно/шторм, отсутствие Remote-вызовов от нативного слоя;
  записать цифры в `STATUS.md`.
- **Готово, когда:** 60 FPS на ПК в шторм (или зафиксированная причина), parts ≤ бюджета.

### 12.11 · Скриншоты погоды
- **Действие:** 3 кадра одного места: ясно / туман / шторм; сравнение в одном ряду.
- **Готово, когда:** 3 PNG одного и того же ракурса (ясно / туман / шторм) в
  `ART_ASSETS/screenshots/weather/`, сложены в один ряд; **проверка**: силуэт острова
  и линия горизонта читаются во всех трёх кадрах, в шторм не «съедены»
  (визуальное сравнение, подпись в `STATUS.md`).

## Риски и грабли

- **Соблазн «сделать объёмные облака мешами»** — уже проверено, что не работает. Не тратить сессии.
- **`Clouds` в `Lighting`** — невидимы; только под `Workspace.Terrain`.
- **Пуфы без лимита** — просадка FPS и «мыло» перед камерой.
- **Разная погода на клиентах** — детерминизм по seed + серверный источник фазы.

## Чего в этой фазе НЕ делаем

- Гроз/молний, volumetric-облаков, погодных событий на весь мир (кросс-шард — после альфы).
- Физики полёта корабля в облаках — только влияние на качку (Ф10).
