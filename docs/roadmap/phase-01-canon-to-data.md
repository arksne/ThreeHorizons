# Ф1 · Канон → данные

> **Цель:** перевести весь лор из `docs/` в машиночитаемые таблицы без Roblox-зависимостей.
> После фазы любую цифру игры можно проверить: она лежит в JSON и ссылается на раздел канона.
> **Зависит от:** Ф0 · **Выход:** `GAME_DESIGN/*.json` + валидатор + `bundle.json` · **Сессий:** 2
> **Канон:** `THREE_HORIZONS_PROJECT_BIBLE.md`, `BALANCING_SPEC`, `SPECS_COMBINED`, `world/*`

## Правила фазы

- Один документ канона → один (или несколько) JSON. В каждом файле — поле `sources` со списком
  `docs/<файл>#<раздел>`, чтобы потом можно было проверить происхождение цифры.
- Никакой логики в данных: только значения и ссылки по id. Формулы — в коде (Ф5/Ф9).
- Все спорные числа помечаются `"status": "PROPOSED"` — станут `APPROVED` после гейм-тестов (Ф9).

## Шаги

### 1.1 · Карта «канон → данные»
- **Действие:** составить `docs/roadmap/canon-map.md`: таблица `документ → раздел → JSON-файл`.
- **Результат:** ни один пункт библии не остаётся «только текстом».
- **Готово, когда:** в таблице ≥ 40 строк, у каждого JSON есть источник.
- **Канон:** все файлы `docs/`.

### 1.2 · `GAME_DESIGN/Factions.json`
- **Действие:** 3 фракции (Арквейн, Вальмер, Гринвальд) + 2 внефракционных (Эстерхольм, Чёрная Гавань):
  `id, name, capital, island, role, resource, government, specializations[4], antagonistHouse,
  districts[8], paletteTokens[7]`.
- **Готово, когда:** каждая фракция имеет ровно 4 специализации и 8 районов из `CITY_LAYOUTS.md`,
  палитра ссылается на токены `DESIGN_TOKENS.md`.
- **Канон:** Bible §2; `world/CITY_LAYOUTS.md`; `DESIGN_TOKENS.md`.

### 1.3 · `GAME_DESIGN/Heroes.json`
- **Действие:** 6 героев (3 пары М/Ж): `id, name, gender, age, faction, profession, startPoint, hook`.
  Возрасты — зеркальные: 24 / 26 / 23 (C-04).
- **Готово, когда:** возраст и профессия совпадают с библией §3, у каждого героя есть стартовая точка
  (Эстерхольм как точка встречи).
- **Канон:** Bible §3; `CONTRADICTIONS.md` C-02, C-04.

### 1.4 · `GAME_DESIGN/Goods.json`
- **Действие:** товары и цепочки: дерево→доски, руда→металл→детали, зерно→мука→хлеб,
  волокно→ткань→одежда, эфир-сырьё→топливо. Отдельно — 3 стратегических лимитных
  (топливо `#3FA7FF`, аквакристалл `#7FD4FF`, зерно `#D8A93B`).
- **Готово, когда:** у каждого товара `id, tier, inputs[], timeSec, outputQty, basePrice, strategic`.
- **Канон:** Bible §6; `DESIGN_TOKENS.md` §«Стратегические ресурсы»; `CONTRADICTIONS.md` C-09.

### 1.5 · `GAME_DESIGN/Prices.json`
- **Действие:** стартовые цены: корпуса 800 / 3000 / 9000, обслуживание 2 %/рейс, доход мастерской
  ~40/игрочас, шторм ×1.5 износа, пираты — до 30 % груза.
- **Готово, когда:** все значения со `"status": "PROPOSED"` и ссылкой на `BALANCING_SPEC`.
- **Канон:** `SPECS_COMBINED.md` §BALANCING.

### 1.6 · `GAME_DESIGN/Ships.json`
- **Действие:** 3 корпуса (лёгкий 18×6, средний 32×10, тяжёлый 48×15 м; борт 2.5/3.5/4.5 м;
  мачта лёгкого ≤14 м), 10 категорий модулей (двигатель, топливо, корпус, палуба, паруса,
  вооружение, трюм, навигация, интерьер, флаг), лимиты (масса/размер/мощность/вместимость),
  6 ролей экипажа.
- **Готово, когда:** любой корабль собирается комбинацией модулей, интерьер обязателен флагом.
- **Канон:** Bible §4; `MASTER_SCALE_SPEC.md` §4.

### 1.7 · `GAME_DESIGN/Professions.json`
- **Действие:** 12 навыков (инженерия, кузнечное дело, строительство, навигация, судовождение,
  торговля, земледелие, животноводство, стрельба, фехтование, ремонт, управление предприятиями),
  гейты: простые 1–5 ч, сложные 20+ ч.
- **Готово, когда:** у каждого навыка есть 3–5 уровней с порогами времени и эффектом.
- **Канон:** Bible §5; `SPECS_COMBINED.md` §BALANCING.

### 1.8 · `GAME_DESIGN/Routes.json`
- **Действие:** 4 грузовых маршрута (Арквейн↔BH, Вальмер↔BH, Гринвальд↔BH, Эстерхольм↔BH)
  + пиратский рейд на Арквейн↔BH; расстояния, время при 18 м/с, эскорт-точки, промежуточные склады.
- **Готово, когда:** времена сходятся с `travel_times` (Ф2.7), маршруты не пересекают острова.
- **Канон:** `world/TRADE_ROUTES.md`; `WORLD_MASTER_MAP.md`.

### 1.9 · `GAME_DESIGN/Buildings.json`
- **Действие:** 7 классов (дом малый 8×10, средний 10×14, большой 14×18, торговый 12×18,
  таверна 18×24, мастерская 12×20, склад 20×35), функции, нужен ли интерьер, бюджет боксов.
- **Готово, когда:** у каждого класса есть размер, функция, `interior: true/false`, `boxBudget`.
- **Канон:** `world/BUILDING_CATALOG.md`; `QUALITY_ASSURANCE.md` Gate A-1 (≤60 боксов).

### 1.10 · `GAME_DESIGN/Weather.json`
- **Действие:** 4 состояния (clear/overcast/fog/storm) + эффекты: видимость, навигация, посадка,
  износ, дрейф, множители; длительность цикла и переходы.
- **Готово, когда:** для каждого состояния заданы все 4 эффекта и параметры облаков
  (`Cover`, `Density`, `Atmosphere`) из `CLOUD_SYSTEM.md` §2.1.
- **Канон:** Bible §7; `CLOUD_SYSTEM.md`; `SPECS_COMBINED.md` (ANIMATION/CAMERA — камера в шторм).

### 1.11 · `GAME_DESIGN/NPC.json` и `Quests.json`
- **Состав:** 5 NPC с расписанием (3 состояния: утро/день/ночь) и 3 квеста
  (по одному на героя): выдать, условия, награда, `txId`-правило.
- **Готово, когда:** квест нельзя выполнить дважды (флаг), NPC не «телепортируется» вне расписания.
- **Канон:** Bible §7 (NPC/события); `ARCHITECTURE.md` §3 (идемпотентность).

### 1.12 · Валидатор данных `tools/validate_design.py`
- **Действие:** проверять: JSON-схему, уникальность `id`, существование ссылок (фракция↔палитра,
  товар↔цена, модуль↔слот), замкнутость цепочек, сумму времени крафта.
- **Готово, когда:** `python -X utf8 tools/validate_design.py` → `DESIGN OK`; специально испорченный
  файл даёт внятную ошибку с файлом и полем.

### 1.13 · `GAME_DESIGN/bundle.json` для Luau
- **Действие:** генератор `tools/bundle_design.py` — склеивает JSON в один файл + печатает Luau-модуль
  `Config/Bundle.lua` (таблицы), чтобы не парсить JSON в рантайме.
- **Готово, когда:** `bundle.json` байт-в-байт воспроизводим, `Bundle.lua` компилируется `luau-compile`.

## Definition of Done фазы

- [ ] 12 JSON-файлов + `bundle.json` + `Bundle.lua`.
- [ ] `validate_design.py` зелёный, негативный тест проходит.
- [ ] `canon-map.md` покрывает все разделы библии (≥40 строк).
- [ ] Ни одного числа «из головы»: у каждого — источник или статус PROPOSED.
- [ ] Тег `v0.2.0`, бэкап, запись в CHANGELOG.

## Риски и грабли

- **Разные цифры в разных доках.** Пример: веса/цены есть и в библии, и в BALANCING — выбираем один
  источник, второй помечаем ссылкой. Расхождение фиксируем в `docs/CONTRADICTIONS.md`.
- **Слишком «умные» данные.** Не кладите формулы в JSON — только числа и id.
- **Забыть `status: PROPOSED`** — потом балансные цифры будут выглядеть каноном и их страшно менять.

## Чего в этой фазе НЕ делаем

- Не пишем игровую логику и не трогаем Roblox.
- Не рисуем UI по этим данным (это Ф10) и не строим здания (Ф4).
