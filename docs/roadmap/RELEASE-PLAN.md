# ПЛАН РЕЛИЗА — что входит, в каком порядке, когда «собрано»

> Отвечает на вопрос: «по роадмапу собрали проект — что дальше?». Роадмап (`ROADMAP_0.1.md`) —
> это 23 фазы; этот документ — **релизная точка** и правила приёмки.

## Три уровня готовности

| Уровень | Что значит | Что входит | Проверка |
|---|---|---|---|
| **Срез** | вертикальный кусок, который можно запустить и поиграть | Ф0–Ф16 (основа, данные, геометрия, стиль, арт, мир, корабли, механики) | гейт R-1, плей-тест 2 клиента |
| **Альфа** | игра целиком, но с заглушками | Ф0–Ф21 (все фазы, включая бой, звук, локализацию, флот, сюжет, фракции) | гейт R-1 + сквозной smoke |
| **Релиз v1.0** | игра, в которую можно пригласить людей | все 23 фазы + публикация | финальный DoD (ниже) |

## Финальный DoD — «проект собран»

Отмечается только когда **все** пункты выполнены. Один невыполненный — релиз не выходит.

| # | Пункт | Как проверить |
|---|---|---|
| 1 | Все 23 фазы закрыты, у каждой — тег и бэкап | `git tag` содержит 23 тега; `backups/` содержит 23 копии |
| 2 | Все 239 шагов в `PROGRESS.json` = `done` | `python -X utf8 tools/make_progress.py` показывает `done=239` |
| 3 | Валидатор данных зелёный | `python -X utf8 tools/validate_design.py` → `DESIGN OK` |
| 4 | Валидатор геометрии зелёный | `python -X utf8 tools/validate_world.py` → `WORLD OK` |
| 5 | Преflight зелёный (код + арт) | `pwsh -File tools/preflight.ps1 -Art` → `PREFLIGHT OK` |
| 6 | **Сквозной smoke**: игра грузится и проходится целиком | `tools/smoke.ps1` → `SMOKE OK`: сборка `.rbxlx`, загрузка, посадка в игру, движение, крафт, квест, сохранение, rejoin |
| 7 | Все 50 требований Bible закрыты | `docs/roadmap/bible-coverage.json` → ни одной `ДЫРА` |
| 8 | Каждая фаза имеет скриншот-доказательство | `ART_ASSETS/screenshots/phase-XX/` — по 1+ на фазу |
| 9 | Ни одной строки текста в коде (локализация) | поиск литералов в `ROBLOX_IMPLEMENTATION/src` → 0 пользовательских строк |
| 10 | Ни одного цвета вне `Style.json` | `tools/validate_design.py` сверяет палитры; расхождений 0 |
| 11 | Производительность в норме на ПК и мобильном | ПК ≥ 60 FPS, мобилка ≥ 30 FPS, parts ≤ 8 000 — таблица в `STATUS.md` |
| 12 | Античит-тесты пройдены | дублей денег/предметов нет; подмена цены клиентом отклонена |
| 13 | Сохранения переживают rejoin | 3 цикла leave/rejoin без потерь и дублей |
| 14 | Закрытая альфа проведена | ≥ 50 участников **или** ≥ 100 часов сессий; топ-10 проблем собраны |
| 15 | `CHANGELOG.md` и `DECISIONS.md` полны | запись на каждый релиз; все решения со статусом APPROVED |
| 16 | `README.md` — инструкция запуска с нуля | новый человек запускает по README без вопросов |

## Сквозной smoke-тест (пункт 6)

Отдельный инструмент `tools/smoke.ps1` (создаётся в Ф22). Проверяет **всё вместе**, а не по частям:

1. `rojo build` → `.rbxlx` собирается без ошибок.
2. Плейс открывается в Studio, `Play` стартует без ошибок в Output.
3. Игрок появляется в безопасной точке, проходит 10 м, не проваливается.
4. Квартал построен: 12–15 домов, двери на улицу, причал у воды.
5. Корабль у причала: ватерлиния верна, F швартует, W разгоняет.
6. Крафт: запуск списывает вход, по таймеру выдаёт выход, повтор не выдаёт второй.
7. Квест: проходится, награда одна, повторная сдача невозможна.
8. Чёрный рынок: сделка есть в экономике, но **нет** в журнале аудита.
9. Захват: чужой корабль меняет владельца, груз переносится.
10. Rejoin: деньги, груз, собственность, квесты, навыки не потеряны и не удвоены.
11. Погода синхронна у 2 клиентов; в шторм видимость падает.
12. Локализация: переключение RU→EN меняет все видимые строки.

Итог: `SMOKE OK` или список упавших пунктов с номером.

## Приёмка фаз

- **Кто закрывает фазу:** владелец. Агент готовит и **предлагает**, решение принимает владелец.
- **Что требуется для предложения:** выполненный критерий «готово, когда» + скриншот или цифра из Output
  + запись в `CHANGELOG.md` + бэкап + тег.
- **Что делает владелец:** смотрит evidence, принимает или отклоняет с указанием, что не так.
- **Правило:** если критерий выполнен, но выглядит неправильно — это тоже отклонение, и оно пишется в `DECISIONS.md`.

## Откат фазы

Фаза провалилась посреди работы. Что делать:

| Ситуация | Действие |
|---|---|
| Шаг не начат | Откат не нужен: фаза просто остаётся открытой |
| Шаг начат, данных мало | Откатить **шаг**: `git revert` коммита шага, вернуть статус в `PROGRESS.json` в `in_progress` |
| Шаг начат, данных много | Оставить коммиты, но откатить **фазу**: `git revert` до последнего тега предыдущей фазы, тег фазы удалить |
| Фаза ломает предыдущие | Откат до последнего зелёного тега; в `CHANGELOG.md` — запись «Ф-N откачена» с причиной |
| Данные уже в `GAME_DESIGN/` и сломали валидатор | Откатить конкретный JSON, починить валидатор, не откатывать фазу целиком |

**Правила отката:**
1. Откат = `git revert`, **не** `reset --hard` — история не переписывается.
2. Откат всегда фиксируется в `CHANGELOG.md` одной строкой: что, почему, на каком теге.
3. Бэкап `backups/v0.N_<дата>/` **не откатывается** — это история, а не рабочее дерево.
4. Тег фазы удаляется только если фаза не была закрыта (иначе тег — навсегда).
5. Решение, из-за которого фазу откатили, пересматривается в `DECISIONS.md` — иначе откат повторится.

## Что дальше после v1.0

Роадмап заканчивается на Ф22. Дальше — `ROADMAP_0.2.md` (создаётся в Ф13.9), куда уходит
всё, что сознательно отложено: PvP вне кораблей, второстепенные фракции-поселения, сезонность,
модерация UGC, кросс-шард, стим-порт. Приоритеты и оценки — в backlog, не в этом документе.
