# Ф0 · База и правила

> **Цель:** пустой, но полностью рабочий скелет проекта: структура папок, инструменты, гейты,
> версии, решения по масштабу. В этой фазе **не создаём ни одного ассета и ни одного модуля игры**.
> **Зависит от:** — · **Выход:** репозиторий + `preflight` + записанные решения S-01…S-06 · **Сессий:** 1–2
> **Канон:** `docs/ARCHITECTURE.md` (§1 дерево), `docs/QUALITY_ASSURANCE.md`, `docs/MASTER_SCALE_SPEC.md`

## Правила фазы

- Всё, что не описано в каноне, здесь не изобретаем — только раскладываем канон по папкам.
- Каждый шаг заканчивается коммитом; после фазы — тег `v0.1.0` и бэкап.
- Скрипты и инструменты живут в `tools/`, данные — в `GAME_DESIGN/`, код — в `ROBLOX_IMPLEMENTATION/`.

## Шаги

### 0.1 · Структура папок
- **Действие:** создать дерево по `ARCHITECTURE.md` §1 и техстеку библии §9:
  `GAME_DESIGN/`, `ART_ASSETS/{models,textures,previews}`, `ROBLOX_IMPLEMENTATION/{src,tests,build}`,
  `STEAM_IMPLEMENTATION/`, `tools/`, `tests/`, `backups/`, `docs/`.
- **Инструмент:** pwsh `New-Item`.
- **Результат:** дерево существует, в каждой папке `README.md` с 3–5 строками «что здесь лежит».
- **Готово, когда:** `Get-ChildItem -Recurse -Directory` показывает все папки, пустые — с `.gitkeep`.
- **Канон:** `docs/ARCHITECTURE.md` §1; `docs/THREE_HORIZONS_PROJECT_BIBLE.md` §9.

### 0.2 · `.gitignore` и правила репозитория
- **Действие:** игнорировать `backups/`, `build/`, `*.fbx`, `*.blend1`, `ART_ASSETS/textures/*.png`
  (кроме манифеста), портативные тулзы, `node_modules/`, `.rojo/`, логи.
- **Результат:** `git status` чистый после генерации ассетов; в репозиторий попадают только скрипты,
  манифесты и документы.
- **Готово, когда:** тестовый `.fbx` и `backups/` не появляются в `git status`.
- **Канон:** `docs/ART_PIPELINE_BLENDER_KIT.md` §7 («FBX не коммитим»).

### 0.3 · Первый коммит и тег
- **Действие:** `git init` (если ещё нет), коммит «v0.1.0: clean lore base», тег `v0.1.0`.
- **Готово, когда:** `git log --oneline` содержит коммит, `git tag` — `v0.1.0`.

### 0.4 · Инвентаризация инструментов
- **Действие:** проверить и записать версии: `git`, `python` (3.x), `node`, `rojo`, `stylua`, `selene`,
  `luau`/`luau-compile`, `blender` (4.x). Результат — `tools/TOOLCHAIN.md` с путями и версиями.
- **Готово, когда:** каждая команда запускается и версия записана; отсутствующие помечены
  «установить в Ф0.5» с ссылкой на установку.
- **Канон:** скилл проекта (пути тулзов) + `docs/ART_PIPELINE_BLENDER_KIT.md` §«Ограничения».

### 0.5 · Установка и фиксация тулчейна
- **Действие:** доставить недостающее: Rojo + плагин Studio, StyLua, selene (std=roblox), Luau CLI,
  при необходимости Node/pnpm. Версии — в `tools/TOOLCHAIN.md`.
- **Готово, когда:** `rojo --version`, `stylua --version`, `selene --version`, `luau-compile --help`
  отвечают без ошибок.

### 0.6 · `tools/preflight.ps1` — единая проверка
- **Действие:** скрипт с 4 проверками: `stylua --check`, `selene`, `luau-compile` всех `.lua` из
  `ROBLOX_IMPLEMENTATION/src`, `rojo build` в `ROBLOX_IMPLEMENTATION/build/`. Флаг `-Art` — позже
  (Ф3, валидатор FBX).
- **Результат:** одна команда, один итог: `PREFLIGHT OK` или список ошибок с файлами.
- **Готово, когда:** на пустом проекте скрипт печатает `PREFLIGHT OK` (0 модулей — не ошибка).
- **Канон:** `docs/QUALITY_ASSURANCE.md` Gate S-1.

### 0.7 · Документы управления: `STATUS.md`, `DECISIONS.md`, `CHANGELOG.md`
- **Действие:** превратить `docs/PROJECT_STATUS.md` в короткий `docs/STATUS.md` (текущая фаза/шаг,
  что проверено фактически, что дальше). `DECISIONS.md` — оставить таблицу + правило ID.
  `CHANGELOG.md` — переписать под формат `## v0.x.y — дата`.
- **Готово, когда:** три файла существуют, шаблонные строки заполнены (пустая фаза = «Ф0 в работе»).
- **Канон:** старые `DECISIONS.md`/`CHANGELOG.md` (структура), `docs/QUALITY_ASSURANCE.md` Gate R-1.

### 0.8 · Правила именования
- **Действие:** зафиксировать в `docs/NAMING.md`: ассеты `TH_<FACTION>_<TYPE>_<VAR>` (+`_L1`,`_L2`),
  звуки `TH_AU_<faction>_<name>_v1`, модули `PascalCase.lua`, события `v1:<Domain>:<Action>`,
  папки `TH_Shared`/`TH_Server`/`TH_Client`.
- **Готово, когда:** документ есть, пример каждого типа приведён.
- **Канон:** `docs/MASTER_SCALE_SPEC.md` §1 (имена), `docs/AUDIO_DESIGN_BIBLE.md` (звук),
  `docs/ARCHITECTURE.md` §3 (сеть).

### 0.9 · Скрипты версии и бэкапа
- **Действие:** `tools/bump_version.py` — поднимает версию в одном `version.json` и печатает блок
  для CHANGELOG; `tools/backup.ps1` — zip `docs/` + `src/` в `backups/vX_<дата>/`.
- **Готово, когда:** `bump_version 0.1.1` меняет `version.json`, бэкап создаёт архив и попадает в `.gitignore`.

### 0.10 · Шаблон рабочей сессии
- **Действие:** `docs/SESSION_TEMPLATE.md`: что прочитать перед стартом (фаза, канон-файлы),
  что записать после (шаг, evidence, коммит), чек-лист гейтов.
- **Готово, когда:** `docs/SESSION_TEMPLATE.md` содержит 4 блока — «что прочитать»,
  «что записать», «проверка», «гейты»; заполнение шаблона занимает ≤ 2 минуты
  (замер: заполнить копию шаблона и засечь время).

### 0.11 · Принять решения S-01…S-06
- **Действие:** занести в `docs/DECISIONS.md` шесть строк из раздела 6 `ROADMAP_0.1.md`
  (метры→studs, сжатие, размер карты, лимит шарда, вода, облака) со статусом `APPROVED`.
- **Готово, когда:** `grep -c 'S-0' docs/DECISIONS.md` = 6, каждая строка имеет основание.
- **Канон:** `docs/MASTER_SCALE_SPEC.md`, `docs/world/WORLD_SCALE.md`, `docs/WORLD_MASTER_MAP.md`,
  `docs/CONTRADICTIONS.md` (P-01…P-03).

### 0.12 · Пустой «эталонный» плейс
- **Действие:** собрать `ROBLOX_IMPLEMENTATION/build/TH_base.rbxlx` из пустого `default.project.json`
  через `rojo build`; открыть в Studio, убедиться, что запускается без ошибок.
- **Готово, когда:** Studio открывает плейс, Output пуст, `preflight` зелёный, тег `v0.1.0` стоит.

## Definition of Done фазы

- [ ] Дерево папок соответствует `ARCHITECTURE.md` §1.
- [ ] `tools/preflight.ps1` → `PREFLIGHT OK`.
- [ ] `tools/TOOLCHAIN.md` с версиями всех тулзов.
- [ ] Решения S-01…S-06 в `DECISIONS.md`.
- [ ] `STATUS.md`, `CHANGELOG.md`, `NAMING.md`, `SESSION_TEMPLATE.md` заполнены.
- [ ] Коммиты по шагам, тег `v0.1.0`, бэкап `backups/v0.1_<дата>`.

## Риски и грабли

- **Ставить тулзы в PATH «на глаз».** Фиксируйте точные пути в `TOOLCHAIN.md`, иначе следующая сессия
  будет искать их заново.
- **Тянуть в репозиторий FBX/текстуры.** Это десятки мегабайт и ломает git; только манифесты.
- **Начать «потихоньку» делать ассеты в Ф0.** Нельзя: без масштаба (Ф2) и данных (Ф1) их придётся
  переделывать.

## Чего в этой фазе НЕ делаем

- Любых моделей, текстур, звуков.
- Игровых модулей (кроме пустого `Main.server.lua` для проверки сборки).
- Правок канона в `docs/` — только техническая реорганизация (`STATUS.md`).
