# Ф3 · Визуальная библиотека (рендеры-эталоны)

> **Цель:** Рендер-эталон каждой модели игры — от пылинки 0.1 м до острова 1200×900 м. Чтобы по нему моделировали, а не по вкусовщине: эталон показывает реальный масштаб, пропорции и силуэт. Масштаб берётся из Ф2, палитры — из DESIGN_TOKENS.
> **Зависит от:** Ф2 (масштаб, карта) · **Выход:** реестр классов `blender/visual_library.json` + ~52 рендера + 9 контактных листов · **Сессий:** 2
> **Канон:** `MASTER_SCALE_SPEC.md`, `QUALITY_ASSURANCE.md` (A-1), атлас «Три горизонта»

## Правила фазы

- Рендер = **3D-блокаут в Blender EEVEE**, не 2D-концепт. Масштаб обязан быть настоящим: та же геометрия, что пойдёт в игру.
- Каждый рендер — с **масштабной линейкой** и подписью (габарит в метрах, tri-бюджет, материалы).
- Рендеры — **эталон**, а не красота. Серый блокаут со светом и линейкой полезнее, чем красивый рендер неправильного размера.
- Ни одного класса вне реестра: если модель есть в игре — у неё есть эталон.
- **Все персонажи — люди, без «злодейской» внешности** (Bible §5): рендер NPC-антигониста не должен
  читаться как «зло» — отличать его должен костюм, а не физиология.
- **Слоган** (Bible §1): «Три горизонта — мир, который живёт» — на титульном экране.

## Шаги

### 3.1 · Реестр классов моделей
- **Действие:** `blender/visual_library.json`: 52 класса в 9 группах — частицы (5), облака (4), корабли (5), здания (12), мир (8), персонажи (5), пропы (8), интерфейс (5), окружение (5). По каждому: id, название, группа, габарит в метрах, tri-бюджет, материалы, назначение.
- **Готово, когда:** `blender/visual_library.json` содержит **52 класса** в 9 группах; у каждого заполнены габарит (м), tri-бюджет и ≥1 материал; json валиден, id уникальны.

### 3.2 · Сцена рендера и камера
- **Действие:** Общая сцена `blender/renders/studio.blend`: единый свет, серый фон, пол с линейкой-эталоном, камера-ортофото для сверху + перспектива 35 мм для фасада. Параметры — из `MASTER_SCALE_SPEC.md` (кадр 1600×900).
- **Готово, когда:** Открытая сцена даёт одинаковый кадр для любой модели: свет/фон/пол одинаковы во всех рендерах (сравнивается по контрольной линейке); один тестовый бокс 1×1×1 м отрендерен и на нём видна линейка.

### 3.3 · Рендер-обёртка `tools/render_library.py`
- **Действие:** CLI: `--class`, `--group`, `--all`, `--out`. Читает `visual_library.json`, строит процедурный блокаут по габаритам, ставит линейку, рендерит в EEVEE, пишет PNG в `ART_ASSETS/visual_library/<group>/`.
- **Готово, когда:** `python -X utf8 tools/render_library.py --group env` создаёт PNG для всех классов группы; в выводе — имя класса, габарит, размер PNG; повторный запуск даёт тот же файл (детерминированно, без случайного сида).

### 3.4 · Частицы и мелочь (5 классов)
- **Действие:** Пылинка, дождь, снег, брызги, искры. Минимальный габарит 0.1 м — на таком масштабе линейка обязательна, иначе частица не читается.
- **Готово, когда:** 5 PNG в `ART_ASSETS/visual_library/particles/`; на каждом — линейка с делением 1 см; частица различима и по габариту совпадает с реестром (±5 %).

### 3.5 · Облака и слои моря (4 класса)
- **Действие:** Клочья (плоскость 12×12 м), три слоя облачного моря Lower/Middle/Upper. Слои различаются только масштабом и Y — рендер это показывает.
- **Готово, когда:** 4 PNG в группе `clouds`; на рендере трёх слоёв видно разницу Y и масштаба, слои не выглядят копией друг друга.

### 3.6 · Здания (12 классов)
- **Действие:** Все 12 классов из `BUILDING_CATALOG.md` + башня, усадьба, стена, ворота. Каждый — с габаритной линейкой по фасаду (высота 8–24 м).
- **Готово, когда:** 12 PNG; на каждом видна горизонтальная линейка по ширине фасада; сумма площадей габаритов совпадает с `Buildings.json` (сверка скриптом).

### 3.7 · Корабли (5 классов)
- **Действие:** 3 корпуса (18×6, 32×10, 48×15 м) + мачта + руль. Видно водяную линию, борта, соотношение мачты к корпусу.
- **Готово, когда:** 5 PNG; для каждого корпуса на рендере видна ватерлиния и подпись «борт X м»; высота мачты лёгкого корпуса ≤ 14 м (по `MASTER_SCALE_SPEC.md` §4).

### 3.8 · Мир, персонажи, пропы, интерфейс (26 классов)
- **Действие:** Остров (рельеф 1200×900 м), 8 элементов рельефа, 5 персонажей, 8 пропов, 5 элементов интерфейса.
- **Готово, когда:** 26 PNG в 5 группах; остров рендерится с линейкой 100 м (видно масштаб острова целиком); персонажи — с линейкой 1.7 м (рост читается); интерфейс — в натуральную величину.

### 3.9 · Контактные листы
- **Действие:** По одному листу на группу (9 шт): сетка 4×4 с подписями класса, габаритом и tri-бюджетом. Сводный лист — на обложку.
- **Готово, когда:** 9 PNG-листов + 1 сводный; на каждом под каждым кадром — id класса и габарит; число кадров на листе совпадает с числом классов в группе.

### 3.10 · Сверка с каноном и фиксация
- **Действие:** Прогнать сверку: для каждого класса габарит из рендера == габарит в реестре == габарит в каноне (Buildings.json / Ships.json). Расхождения — исправить в реестре, а не «подогнать картинку».
- **Готово, когда:** Скрипт сверки проходит без расхождений (0 из 52); тег `v0.3.0`; `docs/DECISIONS.md` — запись «визуальная библиотека v0.1 зафиксирована»; бэкап.

- [ ] ~52 рендера в `ART_ASSETS/visual_library/` + 9 контактных листов.
- [ ] Сверка габаритов рендер ↔ реестр ↔ канон: 0 расхождений.
- [ ] Каждый рендер с масштабной линейкой.
- [ ] Тег `v0.3.0`.

## Риски и грабли

- **Рендер без линейки — половина пользы.** Масштаб не проверить — зачем рендер.
- **Процедурный блокаут ≠ финальная модель.** Это эталон формы, а не замена арту (Ф6).
- **Blender жрёт CPU** — только через обёртку с `--threads 2`.

## Чего в этой фазе НЕ делаем

- Не делаем финальные модели и текстуры — это Ф4–Ф6.
- Не рендерим интерьеры — они в Ф10.
- Не готовим 3D-анимацию — только статичные кадры.
