# Ф3 · Арт-дирекшн и стиль

> **Цель:** превратить стиль из прозы в данные, которые проверяются. Сейчас канон разбросан:
> палитры — в `Factions.json`, свет и Atmosphere — в `Weather.json`, UI-токены — в `constants.json`,
> а материалы Roblox, стиль-формула и приоритет «текст важнее арта» (D-001) — **нигде**.
> Эта фаза собирает всё в `GAME_DESIGN/Style.json` и даёт чек-лист, по которому gate A-1
> отклоняет ассет, который «примерно похож».
> **Зависит от:** Ф2 (масштаб) · **Выход:** `GAME_DESIGN/Style.json` + `docs/STYLE_BIBLE.md` + gate A-1 стиля · **Сессий:** 2
> **Канон:** `DESIGN_TOKENS.md`, `VISUAL_DESIGN_BIBLE.md`, `world/WORLD_PALETTE.md`, `QUALITY_ASSURANCE.md` (A-1)

## Правила фазы

- **Стиль-формула** (Bible §1): Stylized Realism + Medieval Maritime + Vintage Exploration.
  Это не лозунг, а фильтр: рендер, где стиль не читается, — негодный.
- **Приоритет текста над артом** (D-001): при конфликте атласа с Master Prompt побеждает текст.
  Атлас — референс, не источник правил. Спор «похоже на картинку» решается каноном.
- **HEX — только из `DESIGN_TOKENS.md`.** «Примерно похожий цвет» запрещён.
- **Каждый ассет ссылается на токены** и имеет статус `concept|blockout|final|lod` + имя `TH_*`.
- **Концепт ≠ модель:** рендер без LOD и коллизий моделью не считается.
- **Слоган** (Bible §1): «Три горизонта — мир, который живёт» — на титульном экране.

## Шаги

### 3.1 · Стиль-формула в данных
- **Действие:** `GAME_DESIGN/Style.json`: `styleFormula` = «Stylized Realism + Medieval Maritime +
  Vintage Exploration», плюс расшифровка по осям — реализм форм, средневековая морская техника,
  винтажная палитра и типографика. Отдельно — анти-примеры (что НЕ делаем): не фэнтези, не
  стимпанк, не мультяшно, не гиперреализм.
- **Готово, когда:** `Style.json` содержит `styleFormula` с тремя составляющими и ≥ 4 анти-примера;
  формула дословно совпадает с Bible §1 (автосверка).

### 3.2 · Палитры трёх фракций
- **Действие:** в `Style.json` — 21 токен фракций с HEX, назначением и материалом Roblox
  (из `DESIGN_TOKENS.md`): Арквейн (строгий, индустриальный), Вальмер (светлый, торговый),
  Гринвальд (природный).
- **Готово, когда:** в `Style.json` **21 токен** (7 × 3 фракции), у каждого HEX, применение и
  материал; HEX совпадают с `DESIGN_TOKENS.md` (автосверка, 0 расхождений); наборы совпадают
  с `Factions.json → paletteTokens`.

### 3.3 · Свет и атмосфера по фракциям
- **Действие:** в `Style.json` — свет каждой столицы: `ColorTemp` 6500K (Арквейн), 5600K (Вальмер),
  5200K (Гринвальд), экспозиция −0.2 / яркий день / насыщенность +0.1; общие Atmosphere
  Density 0.35, Haze 2, Clouds Cover 0.6; шторм — Density 0.7.
- **Готово, когда:** значения совпадают с `DESIGN_TOKENS.md` §«Свет и атмосфера» (автосверка);
  в Play смена столицы меняет ColorTemp — сверка по Output.

### 3.4 · Материалы Roblox по назначению
- **Действие:** в `Style.json` — колонка Material из `DESIGN_TOKENS.md`: Slate, Cobblestone,
  WoodPlanks, Fabric, Metal, DiamondPlate, Plaster, Sandstone, Limestone, Marble, Wood, Brick.
  Токен → материал + назначение (крыши/стены/балки/акценты/…). Сейчас в данных нет ни одного
  материала — красить нечем.
- **Готово, когда:** у **всех 21+7 токенов** в `Style.json` указан материал Roblox и применение;
  каждый материал из списка существует в Roblox (сверка с каноном, 0 неизвестных).

### 3.5 · UI-токены: все общие
- **Действие:** в `Style.json` — 7 общих токенов: INK #1E1A14, PARCHMENT #E8DCC0,
  PARCH_DARK #CBB98F, BRASS #B08D3E, WOOD_UI #3A2A1C, DANGER #8C2B1B, FOCUS_BLUE #2E4E7E.
  Сейчас в `constants.json → ui.tokens` только 4 (нет WOOD_UI, DANGER, FOCUS_BLUE) — они
  разъедутся между UI и кораблём.
- **Готово, когда:** в `Style.json` **7** общих токенов; `constants.json → ui.tokens` ссылается
  на `Style.json` (дублей нет — автосверка «0 токенов в двух местах»).

### 3.6 · Приоритет текста над артом
- **Действие:** в `Style.json` — правило `artPriority: "text"`: при конфликте атласа с Master
  Prompt / Bible побеждает текст; атлас — референс формы и палитры, не правил. Список
  разрешённых расхождений (то, что уже признано ошибкой генерации: «Морвей/Моряк», «фермер»
  как специализация, «древние руины» с мистикой, 0.48 км² Гавани).
- **Готово, когда:** в `Style.json` есть `artPriority: "text"` и список ≥ 4 признанных
  расхождений; все они совпадают с `CONTRADICTIONS.md` (C-01…C-12) — автосверка.

### 3.7 · Gate A-1: чек-лист стиля
- **Действие:** чек-лист худконтроля как данные (`Style.json → gateA1`): 8 пунктов — HEX из
  токенов, масштаб по `MASTER_SCALE_SPEC`, имя `TH_*`, статус `concept|blockout|final|lod`,
  материалы ≤ 3, UV есть, LOD-соотношения 35 %/8 %, пивот в основании.
- **Готово, когда:** чек-лист из 8 пунктов **исполняется** (не «написан»): прогон по 1 тестовому
  ассету даёт вердикт OK/FAIL по каждому пункту; на испорченном ассете — FAIL с указанием пункта.

### 3.8 · Библия стиля
- **Действие:** `docs/STYLE_BIBLE.md` — человеческая сводка: стиль-формула, 3 палитры с HEX,
  материалы, свет, UI-токены, приоритет арта, чек-лист A-1. Один документ вместо трёх.
- **Готово, когда:** `docs/STYLE_BIBLE.md` есть; все числа в нём совпадают с `Style.json`
  (автосверка, 0 расхождений); на нового человека работает как справочник.

## Риски и грабли

- **«Примерно похожий цвет»** — убийца единого стиля: только точное HEX из токенов.
- **Токены в двух местах** (данные + константы) — разъедутся: источник один, `Style.json`.
- **Стиль-формула как лозунг** — без анти-примеров она ничего не запрещает.
- **Gate A-1 без исполнения** — чек-лист, который никто не запускал, не работает.

## Чего в этой фазе НЕ делаем

- Не рендерим модели — это Ф4 (визуальная библиотека).
- Не делаем текстуры — это Ф6.
- Не верстаем UI — это Ф14.
